Scope and legal noticeขอบเขตและข้อสงวนทางกฎหมาย

Google Consent Mode changes how Google tags behave based on consent signals. It does not by itself make a site compliant with GDPR, Thailand PDPA, or another law. Each customer remains responsible for its legal basis, banner wording, purpose and vendor disclosures, region policy, tag configuration, and legal review.

Google Consent Mode เปลี่ยนการทำงานของ Google tag ตามสัญญาณความยินยอม แต่ตัวมันเองไม่ได้ทำให้เว็บไซต์สอดคล้องกับ GDPR, PDPA ของไทย หรือกฎหมายอื่น ลูกค้าแต่ละรายยังคงต้องรับผิดชอบฐานทางกฎหมาย ข้อความบนแบนเนอร์ การเปิดเผยวัตถุประสงค์และผู้ให้บริการ นโยบายรายภูมิภาค การตั้งค่า tag และการตรวจทานทางกฎหมายเอง

Reject All keeps all optional Google consent types denied. Accept All grants only purposes described to the visitor. A granular choice maps each purpose independently and is never converted to a universal grant.

ปฏิเสธทั้งหมด (Reject All) จะคงประเภทความยินยอมของ Google ที่ไม่จำเป็นทั้งหมดไว้เป็น denied ยอมรับทั้งหมด (Accept All) จะอนุญาตเฉพาะวัตถุประสงค์ที่อธิบายให้ผู้เข้าชมทราบแล้ว ส่วนการเลือกรายข้อจะจับคู่แต่ละวัตถุประสงค์แยกกัน และจะไม่ถูกแปลงเป็นการอนุญาตทั้งหมด

Social Media alone does not grant Google advertising consent. A social service used for advertising must also be classified and disclosed under Targeting/Advertising.

การยินยอม Social Media อย่างเดียวไม่ถือเป็นการยินยอมโฆษณาของ Google บริการโซเชียลที่ใช้เพื่อโฆษณาต้องจัดหมวดและเปิดเผยภายใต้ Targeting/Advertising ด้วย

Choose Basic or Advanced modeเลือกโหมด Basic หรือ Advanced

Netka provides two distinct deployment paths.

Netka มีวิธีติดตั้งให้เลือก 2 แบบที่แตกต่างกัน

Basic mode: block Google tags before consentโหมด Basic: บล็อก Google tag ไว้จนกว่าจะได้รับความยินยอม

Basic mode disables Consent Mode default and update commands and blocks GTM until the visitor makes an affirmative choice. The AutoBlock bootstrap must be placed directly in the page before the Netka banner:

โหมด Basic ปิดคำสั่ง default และ update ของ Consent Mode และบล็อก GTM ไว้จนกว่าผู้เข้าชมจะเลือกยินยอมอย่างชัดแจ้ง ต้องวาง AutoBlock bootstrap ไว้ในหน้าเว็บโดยตรง ก่อนแบนเนอร์ของ Netka:

<script>
window.NKS_CONSENT_MODE_CONFIG = { mode: "basic" };
</script>
<script src="https://cookiebanner.pdpanetka.com/nksAutoBlock.min.js"></script>

Load the customer-specific Netka banner immediately after AutoBlock. Remove static GTM, gtag.js, Google Analytics, Ads and DoubleClick script elements from the page and let the configured Netka loader inject them only after consent. Merely placing AutoBlock above a parser-inserted static script is not a supported blocking guarantee. Recognized Google URLs added later through patched DOM APIs are neutralized as defense in depth. After Accept, Netka loads the saved GTM ID; Reject keeps it blocked. Returning accepted and rejected choices must be checked in browser QA.

โหลดแบนเนอร์ Netka ของลูกค้ารายนั้นต่อจาก AutoBlock ทันที นำ script ของ GTM, gtag.js, Google Analytics, Ads และ DoubleClick ที่ฝังไว้แบบ static ออกจากหน้า แล้วให้ตัวโหลดของ Netka ที่ตั้งค่าไว้ฉีดเข้ามาหลังได้รับความยินยอมเท่านั้น การวาง AutoBlock ไว้เหนือ script แบบ static ที่ parser ใส่เองไม่ถือเป็นการรับประกันการบล็อก URL ของ Google ที่รู้จักและถูกเพิ่มเข้ามาภายหลังผ่าน DOM API ที่ถูก patch จะถูกทำให้ไม่มีผลเป็นการป้องกันอีกชั้น หลังกดยอมรับ Netka จะโหลด GTM ID ที่บันทึกไว้ ส่วนการปฏิเสธจะคงการบล็อกไว้ ต้องตรวจกรณีผู้เข้าชมที่กลับมาพร้อมตัวเลือกยอมรับและปฏิเสธใน QA บนเบราว์เซอร์ด้วย

A monolithic GTM container is released only after Accept All (or all configured optional purposes are granted). A partial granular choice does not release the whole container, because doing so could activate tags for an ungranted purpose. Customers that need granular Basic loading must separate tags by purpose and apply equivalent purpose-specific blocking/triggers during implementation review.

container GTM แบบรวมก้อนเดียวจะถูกปล่อยหลังยอมรับทั้งหมดเท่านั้น (หรือเมื่อวัตถุประสงค์ที่ไม่จำเป็นที่ตั้งค่าไว้ได้รับอนุญาตครบ) การเลือกรายข้อเพียงบางส่วนจะไม่ปล่อยทั้ง container เพราะอาจทำให้ tag ของวัตถุประสงค์ที่ไม่ได้รับอนุญาตทำงาน ลูกค้าที่ต้องการโหลดแบบ Basic รายวัตถุประสงค์ต้องแยก tag ตามวัตถุประสงค์ และใช้การบล็อก/trigger รายวัตถุประสงค์ที่เทียบเท่ากันในขั้นตรวจทานการติดตั้ง

A GTM template cannot retroactively block the GTM container that is already executing it. Therefore, do not describe a CMP tag installed inside GTM as a Basic-mode installation. Use the direct pre-GTM bootstrap above.

เทมเพลต GTM ไม่สามารถย้อนกลับไปบล็อก container GTM ที่กำลังรันตัวมันอยู่ได้ จึงห้ามเรียก CMP tag ที่ติดตั้งใน GTM ว่าเป็นการติดตั้งแบบโหมด Basic ให้ใช้ bootstrap ที่วางก่อน GTM โดยตรงตามด้านบนแทน

Advanced mode: Consent Mode defaults and updatesโหมด Advanced: ค่าเริ่มต้นและการอัปเดตของ Consent Mode

Advanced mode loads consent-aware Google tags with explicit defaults and sends updates after Accept, Reject, granular Save, or withdrawal:

โหมด Advanced โหลด Google tag ที่รองรับความยินยอมพร้อมค่าเริ่มต้นที่กำหนดชัดเจน และส่งการอัปเดตหลังผู้เข้าชมยอมรับ ปฏิเสธ บันทึกการเลือกรายข้อ หรือถอนความยินยอม:

<script>
window.NKS_CONSENT_MODE_CONFIG = { mode: "advanced" };
</script>

For codeless GTM setup, install the Netka CMP Community Template and fire it on Consent Initialization - All Pages. Configure the global and regional rows described below. Google tags may send limited cookieless measurements while the applicable consent signals remain denied.

สำหรับการตั้งค่าใน GTM โดยไม่ต้องเขียนโค้ด ให้ติดตั้ง Netka CMP Community Template และตั้งให้ทำงานที่ Consent Initialization - All Pages แล้วตั้งค่าแถว global และแถวรายภูมิภาคตามที่อธิบายด้านล่าง Google tag อาจส่งข้อมูลการวัดผลแบบจำกัดที่ไม่ใช้คุกกี้ได้ ระหว่างที่สัญญาณความยินยอมที่เกี่ยวข้องยังเป็น denied

Choosing a mode is a customer policy decision. Advanced mode must not be described as automatically compliant with a law.

การเลือกโหมดเป็นการตัดสินใจเชิงนโยบายของลูกค้า ห้ามอธิบายว่าโหมด Advanced สอดคล้องกับกฎหมายโดยอัตโนมัติ

Regional defaults and no-banner measurementค่าเริ่มต้นรายภูมิภาคและการวัดผลในพื้นที่ที่ไม่แสดงแบนเนอร์

Use the same reviewed region policy for banner visibility and Consent Mode defaults. In the Netka GTM template, add:

ใช้นโยบายรายภูมิภาคที่ผ่านการตรวจทานแล้วชุดเดียวกัน ทั้งสำหรับการแสดงแบนเนอร์และค่าเริ่มต้นของ Consent Mode ในเทมเพลต Netka GTM ให้เพิ่ม:

RegionภูมิภาคGranted consent typesประเภทที่อนุญาตDenied consent typesประเภทที่ปฏิเสธ
blank/globalว่าง/globalad_storage,analytics_storage,ad_user_data,ad_personalizationblankว่าง
banner regions, for example DE,FRภูมิภาคที่แสดงแบนเนอร์ เช่น DE,FRblankว่างad_storage,analytics_storage,ad_user_data,ad_personalization

The global row applies where no banner appears. The more-specific regional row requires a choice where the banner is shown. If regional rows are present but the global row is missing, the template inserts a denied global fallback. Duplicate or invalid regional assignments also fail closed.

แถว global ใช้กับพื้นที่ที่ไม่แสดงแบนเนอร์ ส่วนแถวรายภูมิภาคซึ่งเจาะจงกว่าจะบังคับให้ผู้เข้าชมต้องเลือกในพื้นที่ที่แสดงแบนเนอร์ ถ้ามีแถวรายภูมิภาคแต่ไม่มีแถว global เทมเพลตจะใส่ค่า global เป็น denied ให้เอง การกำหนดภูมิภาคซ้ำหรือไม่ถูกต้องก็จะปิดไว้อย่างปลอดภัย (fail closed) เช่นกัน

For a direct-script deployment, set the equivalent policy before AutoBlock:

สำหรับการติดตั้งแบบวาง script โดยตรง ให้ตั้งนโยบายที่เทียบเท่ากันไว้ก่อน AutoBlock:

<script>
window.NKS_CONSENT_MODE_CONFIG = {
  mode: "advanced",
  bannerRegions: ["DE", "FR"],
  grantOutsideBannerRegions: true,
  waitForUpdate: 2000
};
</script>

Replace the example regions with an approved policy. A timeout, missing setting, or geo error is not proof that a visitor is outside a region and must fail closed. A stored user rejection takes priority over a later no-banner result.

แทนภูมิภาคตัวอย่างด้วยนโยบายที่ได้รับอนุมัติแล้ว การหมดเวลา การตั้งค่าที่ขาดหาย หรือข้อผิดพลาดในการระบุตำแหน่ง ไม่ใช่หลักฐานว่าผู้เข้าชมอยู่นอกภูมิภาค และต้องปิดไว้อย่างปลอดภัย (fail closed) การปฏิเสธที่ผู้ใช้บันทึกไว้แล้วมีลำดับความสำคัญเหนือผลแบบไม่แสดงแบนเนอร์ที่ได้ภายหลัง

Google-ready non-TCF bannerแบนเนอร์แบบ Google-ready ที่ไม่ใช้ TCF

When Consent Mode is enabled without TCF, select the Google-ready banner template in the Netka GUI. It must:

เมื่อเปิดใช้ Consent Mode โดยไม่ใช้ TCF ให้เลือก Google-ready banner template ใน Netka GUI ซึ่งต้อง:

  1. explain analytics and, where enabled, personalization/advertising purposes;
  2. provide an affirmative Accept option and a clear Reject/customize path;
  3. expose Google's Business Data Responsibility page inside the banner or its in-banner details;
  4. leave optional categories off until affirmative consent where opt-in applies;
  5. let the visitor reopen preferences and withdraw consent.
  1. อธิบายวัตถุประสงค์ด้านการวิเคราะห์ และวัตถุประสงค์ด้านการปรับให้เหมาะกับบุคคล/โฆษณาในกรณีที่เปิดใช้
  2. มีตัวเลือกยอมรับอย่างชัดแจ้ง และมีทางปฏิเสธ/ปรับแต่งที่ชัดเจน
  3. แสดงลิงก์ไปยังหน้า Business Data Responsibility ของ Google ในแบนเนอร์หรือในรายละเอียดภายในแบนเนอร์
  4. ปิดหมวดที่ไม่จำเป็นไว้จนกว่าจะได้รับความยินยอมอย่างชัดแจ้ง ในกรณีที่ใช้หลัก opt-in
  5. ให้ผู้เข้าชมเปิดการตั้งค่าอีกครั้งและถอนความยินยอมได้

The generated configuration uses consentMode.googleReadyTemplate: true. Netka then preserves the Google privacy link, Accept/Reject controls, optional-off defaults, and a link-capable banner layout. Confirm the rendered GUI and generated configuration during QA.

การตั้งค่าที่สร้างขึ้นจะใช้ consentMode.googleReadyTemplate: true จากนั้น Netka จะคงลิงก์ความเป็นส่วนตัวของ Google ปุ่มยอมรับ/ปฏิเสธ ค่าเริ่มต้นที่ปิดหมวดไม่จำเป็น และ layout แบนเนอร์ที่ใส่ลิงก์ได้ไว้ให้ ตรวจยืนยันหน้าตา GUI และการตั้งค่าที่สร้างขึ้นระหว่าง QA

Verify defaults and updatesตรวจสอบค่าเริ่มต้นและการอัปเดต

Use GTM Preview, Tag Assistant, browser storage, and the Netka diagnostic report on every public landing page. Verify that:

ใช้ GTM Preview, Tag Assistant, storage ของเบราว์เซอร์ และรายงานวินิจฉัยของ Netka กับทุก landing page สาธารณะ แล้วตรวจว่า:

  • Advanced defaults contain ad_storage, analytics_storage, ad_user_data, and ad_personalization before any Google tracking event;
  • Basic mode produces no Consent Mode default/update commands and loads Google tags only after Accept;
  • Accept, Reject, granular Save, and withdrawal produce the expected behavior;
  • returning accepted and rejected choices are restored;
  • no optional cookie is written before the applicable choice;
  • the banner appears inside configured regions and outside-region behavior follows the reviewed policy;
  • the Netka Developer ID is visible in the Google debugging tools.
  • ค่าเริ่มต้นโหมด Advanced มี ad_storage, analytics_storage, ad_user_data และ ad_personalization ก่อนเหตุการณ์ติดตามใด ๆ ของ Google
  • โหมด Basic ไม่สร้างคำสั่ง default/update ของ Consent Mode และโหลด Google tag หลังกดยอมรับเท่านั้น
  • การยอมรับ ปฏิเสธ บันทึกรายข้อ และถอนความยินยอม ทำงานตามที่คาดไว้
  • ตัวเลือกยอมรับและปฏิเสธของผู้เข้าชมที่กลับมาถูกเรียกคืนได้ถูกต้อง
  • ไม่มีคุกกี้ที่ไม่จำเป็นถูกเขียนก่อนผู้เข้าชมเลือก
  • แบนเนอร์แสดงในภูมิภาคที่ตั้งค่าไว้ และการทำงานนอกภูมิภาคเป็นไปตามนโยบายที่ตรวจทานแล้ว
  • เห็น Developer ID ของ Netka ในเครื่องมือ debug ของ Google

A late consent result means that the CMP default or TCF stub was observed after a Google tag began loading. A visible banner does not make this warning safe to ignore.

ผล late consent หมายถึงพบค่าเริ่มต้นของ CMP หรือ TCF stub หลังจากที่ Google tag เริ่มโหลดไปแล้ว การที่แบนเนอร์แสดงอยู่ไม่ได้ทำให้มองข้ามคำเตือนนี้ได้

Google tag gateway and late consentGoogle tag gateway และ late consent

Google tag gateway (GTG) can serve Google tags through a site's first-party infrastructure. One-click CDN enrollment can alter where and when a tag is injected, so the CMP may not control import order.

Google tag gateway (GTG) ให้บริการ Google tag ผ่านโครงสร้างพื้นฐาน first-party ของเว็บไซต์ได้ การลงทะเบียนผ่าน CDN แบบคลิกเดียวอาจเปลี่ยนตำแหน่งและเวลาที่ tag ถูกฉีดเข้ามา ทำให้ CMP อาจควบคุมลำดับการโหลดไม่ได้

When Netka diagnostics report late consent:

เมื่อรายงานวินิจฉัยของ Netka พบ late consent:

  1. Inspect the CDN/tagging configuration and Google's GTG setup documentation.
  2. Use Tag Assistant and browser Network tools to identify the first-party GTG path and confirm whether it begins before the consent default.
  3. If GTG is confirmed, prefer U+C/Advanced Consent Mode for consent-aware tags and configure Data Transmission Controls and Global Consent Defaults for the customer's needs and reviewed region policy.
  4. Alternatively, migrate the implementation into one GTM container and deploy GTM through GTG, or configure GTG manually so the customer controls import order.
  5. Re-run diagnostics on every landing page, including campaign and deep links.
  1. ตรวจการตั้งค่า CDN/tagging และเอกสารการตั้งค่า GTG ของ Google
  2. ใช้ Tag Assistant และเครื่องมือ Network ของเบราว์เซอร์หา path ของ GTG แบบ first-party และยืนยันว่าเริ่มโหลดก่อนค่าเริ่มต้นของความยินยอมหรือไม่
  3. ถ้ายืนยันได้ว่าใช้ GTG ให้เลือก U+C/Advanced Consent Mode สำหรับ tag ที่รองรับความยินยอม และตั้งค่า Data Transmission Controls กับ Global Consent Defaults ตามความต้องการของลูกค้าและนโยบายรายภูมิภาคที่ตรวจทานแล้ว
  4. อีกทางหนึ่งคือย้ายการติดตั้งทั้งหมดเข้าไปใน container GTM เดียวแล้ว deploy GTM ผ่าน GTG หรือตั้งค่า GTG เองเพื่อให้ลูกค้าควบคุมลำดับการโหลดได้
  5. รันการวินิจฉัยซ้ำกับทุก landing page รวมถึงลิงก์แคมเปญและ deep link

U+C/Advanced Consent Mode is Netka's recommended path for GTG-enabled, consent-aware tags because it is compatible with manually controlled GTG. Basic mode remains available when Google tags must be blocked until consent.

U+C/Advanced Consent Mode เป็นแนวทางที่ Netka แนะนำสำหรับ tag ที่รองรับความยินยอมและเปิดใช้ GTG เพราะใช้ร่วมกับ GTG ที่ควบคุมเองได้ ส่วนโหมด Basic ยังใช้ได้เมื่อต้องบล็อก Google tag ไว้จนกว่าจะได้รับความยินยอม
